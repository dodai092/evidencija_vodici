# Guide data updates stay manual, not automated from Google Sheets

We tried automating the weekly `data-2026.js` update by pulling directly from the source Google Sheet (`SHEET_URL` env var, already supported by `scripts/extract_guides.py`), via both a GitHub Actions cron (`.github/workflows/update-data.yml`) and a scheduled cloud agent. Both failed with HTTP 401 — anonymous CSV export only works if the sheet is either "Anyone with the link," published to the web, or read via an authenticated Google service account. The manager who owns the sheet declined public/link sharing, and no Google Cloud project/service account exists to do it privately. Rather than stand up that infra for a once-a-week update, we kept the process manual: someone drops the latest export at `1.1 Evidencija prodaje 26.xlsx` and asks for "update the report," which runs the local-Excel path, sanity-checks the diff, and commits/pushes directly.

`SHEET_URL` support remains in `extract_guides.py` (and the workflow keeps its `workflow_dispatch` trigger) in case a service account gets set up later — it is currently dead in practice, not dead code to delete.
